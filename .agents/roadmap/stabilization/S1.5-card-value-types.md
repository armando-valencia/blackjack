# S1.5 — Named Card Value Types

Branch: `refactor/stabilization-card-value-types`

## Scope

- Add named domain types for card ranks and suits in the card module.
- Keep wire serialization backward-compatible with values such as `AS` and `10H`.
- Update deck creation and game logic to use the named values.
- Migrate S1 tests away from raw rank and suit strings.
- Add focused tests for card construction, string serialization, and deck composition.

## Acceptance criteria

- Card rank and suit concepts have one owning definition.
- Tests use named values rather than repeated literals such as `"A"` and `"H"`.
- Existing frontend card strings remain unchanged.
- No test-only constants duplicate production domain values.
